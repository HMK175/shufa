# 大论文框架与小论文选题定位说明

记录日期：2026-07-01

## 核心判断

大论文结构现调整为三段式：

```text
第 3 章：多模态风格意图理解与目标字图像生成
第 4 章：目标字图像到书写轨迹恢复
第 5 章：execution / 仿真 / 执行前检查
```

这意味着：

- 旧版“第 3 章 = A-route 参数化轨迹生成”的表述不再作为唯一推荐结构。
- 当前 `experiments/llm_style_trajectory` 更适合作为第 4 章 / 第 5 章的 execution 与 precheck backbone。
- 第 3 章在后续大论文阶段可以允许引入深度学习，并基于已有 few-shot font / calligraphy generation 基线做场景化改进。

## 推荐大论文结构

1. 绪论
2. 相关理论与方法基础
3. 面向书法机器人的多模态风格意图理解与目标字图像生成方法
4. 面向目标字图像的书写轨迹恢复方法
5. execution 层、仿真与执行前检查方法
6. 总结与展望

## 当前更推荐的小论文对应章节

当前更推荐的小论文对应第 4 章：

```text
目标字图像到书写轨迹恢复方法
```

或者更完整地写成：

```text
目标字图像到轨迹恢复与执行前检查方法
```

原因：

- 问题更独立，章节边界更清楚
- 可避免与第 3 章的图像生成部分重复
- 与 CalliRewrite 的关系更容易界定为“面向机器人执行的轨迹恢复”，而不是硬拼“任意风格强恢复”
- 更容易复用当前 A-route 中已有的 execution 和 precheck 基础设施

## 第 3 章与第 4 章的关系

推荐表述：

- 第 3 章负责“用户想写什么样的字，以及如何得到目标字图像”
- 第 4 章负责“这张目标字图像如何恢复成书写轨迹”
- 第 5 章负责“恢复出的轨迹如何进入 execution、仿真与 dry-run precheck”

也就是说：

```text
第 3 章输出：目标字图像
第 4 章输出：书写轨迹
第 5 章输出：execution-ready / robot-ready dry-run chain
```

## 当前 `experiments/llm_style_trajectory` 的定位更新

当前默认主线仍然重要，但其论文位置需要更新为：

- 第 4 章的 trajectory / execution 表示基础
- 第 5 章的 workspace、retiming、motion continuity、CoppeliaSim、AUBO dry-run backbone
- 图像到轨迹恢复路线的执行层与检查层支撑环境

它当前不宜再被包装为：

- 强字体风格迁移主结果
- 大论文第 3 章唯一核心创新

## 第 3 章的建议写法

第 3 章不要写成“从零提出一个通用字体生成大模型”，更稳的定位是：

- 基于公开 few-shot Chinese font / calligraphy generation 基线
- 做面向书法机器人下游轨迹恢复任务的场景化改进
- 强调目标字图像的结构稳定、笔画清晰、拓扑可恢复性

因此，第 3 章的创新点更适合放在：

- 多模态风格意图理解
- 目标字符与风格约束组织
- 面向下游轨迹恢复的生成约束
- 图像生成质量与下游恢复质量的联合评价

## 第 4 章的建议写法

第 4 章不要只写成“比 CalliRewrite 更强的图像到笔画恢复”，而应收窄为：

- 面向机器人执行的图像到书写轨迹恢复
- 结合书写先验约束
- 恢复结果可进入 execution-ready 表示
- 同时评价图像相似性与机器人可执行性

## 当前推进顺序

1. 第 4 章优先作为小论文主线推进。
2. 第 4 章先用真实字体 / 书法图像独立成立，不强依赖第 3 章。
3. 第 3 章在后续时间更充裕时，再引入深度学习基线与改进。
4. 最终将第 3 章输出的目标字图像接入第 4 章，再由第 5 章完成 execution / precheck。
