# OCR 人工复核最终汇总设计

## 背景与目标

ChineseStyle 的逐图 OCR 已产生初始标签。人工复核时，为提高效率，用户只为需修改或删除的样本填写记录；未填写的样本默认保留 OCR 结果。本设计把这套人工工作流转换为可重复执行的最终候选集，同时不修改任何人工正在编辑的 CSV。

## 输入与输出边界

输入为只读的 `ocr_labels.csv` 和一个或多个复核 CSV：历史 `manual_overrides.csv`、批量标记表、以及只含待补人工字符的 `correction_entries.csv`。汇总器只在一个新输出目录中写入结果，绝不覆盖输入文件或旧审计产物。

最终输出包括：

- `candidate_manifest.csv`：可用于后续数据集构建的唯一候选图清单；
- `rejected_rows.csv`：明确排除的图；
- `unresolved_rows.csv`：尚未完成、不能进入训练集的图；
- `normalization_report.json`：历史表的列交换和 `aceept -> accept` 等兼容性修复记录；
- `review_finalization_summary.json`：各类数量及失败原因汇总。

## 决策语义

以图片稳定键 `(dataset_id, style_id, source_split, raw_filename)` 联结 OCR 标签和人工记录。

| 人工记录 | 最终处理 |
| --- | --- |
| 无记录，或四项键之外均空 | 保留合法单个汉字 OCR 结果 |
| `reject` | 排除该图 |
| `accept` 加一个合法人工汉字 | 用人工汉字覆盖 OCR 结果 |
| `accept` 但人工字符为空 | 标记为待补；不可进入最终候选 |
| OCR 本身不是单个合法汉字且没有人工改字 | 标记为待补；不可进入最终候选 |

人工字符不能是多字、非汉字或与 `reject` 同时出现。一个样本若在多个表中出现，后面的待补表可用已经填写的人工字补全前面的 `accept` 空字符；其余相互矛盾的有效记录均报错，不猜测覆盖顺序。

历史 `manual_overrides.csv` 中已知的列错位（第三列是图片名、第四列是 `train/test`）只在内存中纠正；拼写 `aceept` 归一为 `accept`，并写入报告，源文件不改动。

## 质量闸门

最终候选必须满足：源图片键存在、最终字符合法、没有未解决复核项，并且同一 `(dataset_id, style_id, character)` 只保留一张图。若发生同字冲突，汇总器写明冲突并拒绝产生可宣称为最终版的候选清单。

这套约束故意把“尚未确认”与“正确”分开：默认保留只适用于 OCR 已经给出合法单字且你没有标记需改的情形；你标记为 `accept` 但尚未填字时，它仍是待处理而不是默认正确。

## 8 位书法家 OCR 诊断

之前的后台任务没有写出结果文件，日志仅显示 Paddle 模型加载。因此先用数张真实图片验证加载、识别与返回数量；若该探针通过，问题属于长任务的可观测性/外部中断而非图片或模型接口错误。随后给长任务增加批次进度输出，并以独立的新输出目录重新启动；不复用不完整目录，也不修改用户的 ChineseStyle 复核文件。
