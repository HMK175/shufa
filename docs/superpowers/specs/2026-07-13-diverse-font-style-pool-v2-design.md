# FontDiffuser 多样化字体风格池 v2 设计

## 背景与问题

现有 v1 数据集虽然已生成 28 个可用风格，但 Noto Sans SC 与 Noto Serif SC 的连续 `wght` 实例占比较大。它们在骨架、结构和字形设计上高度相近，主要差异为笔画粗细；将它们全部作为独立风格会夸大风格数量，并削弱论文中“跨字体风格迁移”的说服力。

v1 仅作为构建器、许可证审计和渲染流程的验证结果保留，不删除，也不与 v2 混合训练。

## 目标

构建独立的 `fontdiffuser_open_dataset_v2`：保留 28 个有效风格、1,000 个字符，并在保持 FontDiffuser 20/3/5 风格划分与 800/100/100 字符划分的前提下，提高字体家族和结构风格的多样性。

## 最终组成规则

- 总风格数固定为 28。
- 常规字体为 21 个，至少来自 8 个不同字体家族；每个家族最多保留 3 个代表样式。
- 书写/书法类为 7 个；每个字体家族最多保留 1 个。
- Noto Sans SC 与 Noto Serif SC 各只保留 Light、Regular、Bold 三个代表字重；不再将 100–900 的连续字重全部计为独立风格。
- 字体家族相同、仅笔画粗细不同的候选不得同时超过 3 个。
- 每个字体候选必须满足：官方上游可追溯、许可证为 OFL-1.1 或 Apache-2.0、覆盖全部 1,000 个候选字符、字体文件和许可证副本均有 SHA-256 记录。

## 候选筛选流程

1. 仅从官方上游项目检索许可证明确的候选字体；不使用商业字体、转载站字体或许可不明确字体。
2. 下载字体文件及许可证副本，记录上游 URL、字体 SHA-256、许可证 SHA-256。
3. 自动检查字体文件非空、Unicode cmap 覆盖全部 1,000 字、渲染结果为 256×256 黑字白底且四边留白不小于 4 像素。
4. 为每个候选生成固定字符预览，由人工排除仅粗细不同、补字质量明显不稳定、字符异常裁切或过度装饰的候选。
5. 按家族上限和常规/书写配额固定 v2 风格清单；不足名额时必须补充新的字体家族，不得以相近字重自动补位。

## 构建与验收

- v2 输出根目录为 `experiments/target_glyph_generation/data/fontdiffuser_open_dataset_v2/`，与 v1 隔离。
- 重新计算确定性的 20/3/5 风格划分；保留既有确定性的 800/100/100 字符划分。
- 预期输出：1,000 张 `ContentImage`、28,000 张 `TargetImage`、字体/字符/划分/失败清单、数据集摘要和人工审计网格。
- 任一许可证、覆盖率、图像边界或样式配额门槛失败时，以非零状态停止，并在失败清单记录原因。
- 数据集构建完成后必须由用户人工检查审计网格；未确认前，不进入 FontDiffuser baseline dry-run 或模型训练。

## 非目标

- 不使用 RHSEDB 或其他许可证不明确的手写数据训练。
- 不修改旧路线代码或现有 v1 数据。
- 本阶段不训练 FontDiffuser，不比较指标，也不生成轨迹或机器人控制输出。
